# 域账号自动关联

此功能属于统计归属，不是企业身份认证。客户端域身份为自报元数据，不赋予后台权限。客户端配套工作见 [Piora #462](https://github.com/kexijiang/pi-desktop/issues/462)。旧客户端不报告域身份时仍可注册和上传。

## 管理员设置

组织设置 → 域账号自动关联：启用自动关联，选择是否自动创建员工，添加允许域及工号规则。例如域 CHINA、纯数字：账号 001234 匹配工号 001234，前导零保留。不存在时可自动创建，姓名暂用工号，部门后续补充。

域名不区分大小写。登录名可保持原样或统一大/小写，格式仅支持纯数字或字母数字下划线连字符，不执行管理员自定义正则。工号在同一组织内全局唯一，无需设置前缀或映射。例如 CHINA\001234 与 OTHER\001234 都关联工号 001234 的同一员工；域名只用于允许列表校验，组织之间仍隔离。更改规则导致冲突时需要人工确认。

默认关闭自动关联。设置有乐观版本检查，冲突时刷新后重试。规则保存后，新注册设备立即应用；已有设备在下一次身份补报时应用，不自动扫描历史身份修改归属。

## 客户端协议

1. 请求 `GET /v1/capabilities`。返回 capabilities 包含 `windows-domain-identity-v1` 才使用以下字段/接口。旧服务器返回 404 或没有该能力时，维持旧协议。
2. 首次注册可在 RegisterInput 中附带可选 windows_identity：

```json
{"account_type":"domain","domain":"CHINA","account_name":"001234","source":"windows_logon"}
```

本地账号使用 account_type=local；未知身份使用 unknown。domain 和 account_name 可为空；source 为 windows_logon 或 unavailable。不可把显示名或用户目录当成域身份。

3. 已注册设备用现有设备 Bearer 凭证调用 `POST /v1/installations/identity`，请求体为 `{ "identity": <上述对象> }`，提供 Idempotency-Key。不接受客户端指定 employee_id 或组织 ID。重复相同补报收敛到同一归属，不创建重复员工/绑定；结果按当前策略返回。不会修改注册原始请求摘要，不消耗接入凭证次数，不删除队列。
4. 读取结果 state、employee_id、binding_source。常见待处理原因：未启用、域不允许、工号格式不符、员工不存在/停用、身份冲突、已有人工绑定。个人设备不匹配不会中断统计上报。

首次绑定从匹配当天（Asia/Shanghai）生效，不回写前一天及更早历史。存在任何人工确认的绑定时保留人工结果。已有自动绑定发生账号变化时进入冲突状态，不静默转移设备；在采集健康点击“绑定员工”，可选择已有绑定期间、归属员工、生效/结束日期并填写原因，保存纠错；也可新增不重叠的绑定期间。纠错后 source 变为 manual。

## 数据与升级

迁移 `0002_domain_identity.sql` 新增域身份数据结构，`0003_global_employee_numbers.sql` 允许多个域账号关联同一员工并清理旧前缀配置；原有迁移文件保持不变。新增安装身份表、员工域账号归属记录表及绑定来源字段，扩展组织设置类型。迁移时默认不自动归属，已有绑定均为 manual。应用部署前执行迁移。若试用旧分支时已生成带前缀的员工，迁移不自动改工号或合并历史归属，需要管理员核对纠错；新规则直接使用无前缀工号。旧版本应用回退需单独确认兼容。

未绑定设备的统计保留在总览，页面提示未关联员工；员工明细仍按明确归属展示。采集健康展示匹配原因和绑定来源。无员工时，手工绑定弹窗提供创建入口并禁用无效确认。

## 验证范围

使用合成域账号、隔离 PostgreSQL 和浏览器验证。实际公司 Windows 域账号采集由客户端任务验收，不能把后端夹具测试视为已验证真实域环境。当前运行中的本地 v0.1.0 服务不会因源码修改自动升级。

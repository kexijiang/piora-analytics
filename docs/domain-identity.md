# 账号自动关联

此功能只决定统计归属，不是企业身份认证，不授予后台权限。工号在组织内唯一；不同域的同一工号归到同一员工，组织之间隔离。

## 默认行为

不需要勾选开关、配置域名或保存规则。新注册与身份补报自动匹配员工，不存在时自动创建，姓名暂用员工编号，部门可后续补充。

- 域账号使用客户端明确报告的域登录名作为工号。例如 CHINA\001234 与 OTHER\001234 都匹配 001234，不限定域名，不做前缀映射，保留前导零和大小写。
- 本地账号使用报告的账号名；本地身份未包含账号名时，使用注册时的 windows_username。旧客户端未报告身份时也使用该注册用户名，不将其冒充为已验证域身份。
- 编号接受不超过 64 个字符的 Unicode 字母、数字、点、下划线或连字符。未知身份、无效账号、停用员工及与已有归属冲突的账号不强行关联。设备仍可上传数据。
- 同一编号归到同一员工，包括本地账号；不同电脑若使用相同通用本地账号也会合并统计。此规则适用于组织内账号唯一的部署约定。
- 存在任何人工确认的历史、当前或未来绑定时，保留人工决定，不额外创建员工。已有自动绑定发生账号变化时显示冲突，需管理员纠错。

组织设置只展示上述行为说明。旧版 settings/identity GET/PATCH 接口保留兼容：返回 enabled=true、auto_create=true、rules=[]，旧开关和规则不再影响匹配；PATCH 仍检查版本，但不能关闭默认行为。

## 历史回补

升级并启动 worker 后，分批扫描已有安装与身份，不需要客户端重新注册或再次上报。每批最多处理 50 台，处理标记与员工创建、绑定在同一事务提交；中断后继续，重复运行不会重复创建。已撤销设备只标记完成，不新增归属。

首次自动绑定涵盖全部历史与未来日期，因此已有统计和后续补传的旧事件都能按员工展示。旧版从匹配当天开始的单个、无结束日期自动绑定也向历史延伸。人工绑定不改写；多段或有结束日期的已有自动绑定不扩展。

报表按安装日汇总与绑定期间实时关联，不复制或伪造历史事件，也不增加原有统计总量。尚未上传或已被保留策略清理的数据不会被恢复。

## 客户端协议

1. `GET /v1/capabilities` 返回 windows-domain-identity-v1 后，首次注册可附带 windows_identity。旧客户端仍可注册和上传。
2. 域身份示例：

```json
{"account_type":"domain","domain":"CHINA","account_name":"001234","source":"windows_logon"}
```

本地账号使用 account_type=local；未知身份使用 unknown。domain 和 account_name 可为空；source 为 windows_logon 或 unavailable。不从显示名、目录名猜测域工号。

3. 已注册设备用现有设备 Bearer 凭证调用 `POST /v1/installations/identity`，请求体为 `{ "identity": <身份> }` 并提供 Idempotency-Key。不接受客户端指定员工或组织 ID。补报不消耗注册凭证、不重置身份、不删除上传队列。
4. 读取 state、employee_id、binding_source；新自动绑定的来源为 automatic，旧域绑定仍可能为 domain，人工纠错为 manual。

采集健康中的“绑定员工”支持人工纠错，生效日期留空代表全部历史。保存后人工归属优先，不再自动覆盖。

## 数据升级与验证边界

保留已部署的 0001–0003 迁移；新增 `0004_automatic_identity.sql`，增加可续跑的回补标记、automatic 来源及无起始日期的绑定期间，归一化旧策略。先迁移，再启动新版 API 和 worker。旧应用不识别新来源与空起始日期，回退需要使用升级前备份或确认兼容。

自动关联与回补使用隔离 PostgreSQL 的合成账号验证，浏览器检查覆盖固定说明、自动归属及人工纠错。真实公司 Windows 域账号采集与多员工部署仍需在公司环境验收，不能将夹具测试等同于真实域接入。

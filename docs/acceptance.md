# 验收矩阵

## 本设计包自动检查

1. OpenAPI 可解析、所有 request/response/event 示例通过 Schema；事件额外敏感字段被拒绝。
2. 生成的 TypeScript 类型与原型编译；构建成功；生成物无漂移。
3. PostgreSQL 18 空库迁移；重复事件唯一键、跨组织外键、绑定重叠、区间并集的数据库用例。
4. 协议参考算法：跨午夜拆分、跨设备区间合并、重复 ACK、int64、Token 缺失和规范状态。
5. Playwright：筛选确实更新数据、员工抽屉、请求详情、主题、viewer 不显示管理编辑、错误/空状态、CSV、响应式与截图。

这些证明设计产物可用，不证明尚未实现的生产 API、Windows 埋点或真实模型计量正确。

## 后续必须通过的生产测试

| 范围 | 操作 | 必须看到 |
|---|---|---|
| 身份 | 两个不同 Windows 用户都叫 admin | 生成不同安装；未经确认不合并人数 |
| 身份 | 同一员工两台电脑同时前台 10 分钟 | 活跃时长 10 分钟、设备 runtime 20 分钟 |
| 冷启动/打开 | 手动启动、托盘唤起、失焦恢复、升级自启 | 逐项匹配 launches/opens 定义，focus 不虚增 |
| 时长 | 运行 5min、锁屏 5min、sleep 10min | 不把锁屏/sleep 算活跃；sleep 不算 runtime |
| Query | 重复网络发送同 key，再手动同文本新 key | Query=2，不是网络请求次数 |
| Query | 一次 room 输入分发 4 Agent；自动任务一次 | 人工 Query=1；其他来源单列 |
| 模型 | 一次请求失败重试 2 次后成功 | 3 calls；1 Query；所有已知用量相加 |
| 模型 | completeSimple/虚拟模型/fallback/辅助 vision | 只记具体调用；覆盖所有入口 |
| 模型 | SDK 默认全 0 但供应商无 usage | unavailable，显示 — 与缺失数 |
| 文件 | new/edit/审批拒绝/工具失败/二进制/CRLF | 真实读前后对账；未知不填 0 |
| 文件 | 2 个任务并发修改同路径、外部工具同时改 | 有序已知或 concurrent_change，不能双计计划内容 |
| 上传 | ACK 前后分别杀 API/断连接，再重复发 | ACK 前保留；ACK 后重传 duplicate；总量不变 |
| 上传 | 相同 ID 改内容 / 跨月重发 / 乱序终态 | 冲突隔离 / 去重 / revision 正确 |
| 上传 | 500 台同一时刻开机或网络恢复 | 请求分散；429 不导致重试风暴 |
| 上传 | 离线 7 天与 31 天 | 7 天补齐；超限明确缺口，不伪造完整 |
| 聚合 | Worker 处理中到达新事件 / 租约过期 | 新版本继续处理；旧 worker 不能覆盖新结果 |
| 归属 | 修改 120 天前误绑定 | 通过安装日维度重映射，原始 90 天过期不影响 |
| 权限 | viewer 手工请求 PATCH / 跨组织 ID | 403 / 404；不靠前端隐藏 |
| 导出 | 姓名以 = 开头、下载过期/撤销会话 | CSV 不执行公式；不能越权下载 |
| 时钟 | 手动调系统时间、跨午夜、恢复睡眠 | 时长单调、拆日正确、可疑时间不静默改日期 |
| 灾备 | 从备份恢复到临时环境 | receipt、原始事件和聚合对账，验证真实 RPO/RTO |

试点对账至少覆盖 5 位员工、3 天、100 次人工提交、20 次文件修改、两种供应商（含无 usage）。人工记录不包含真实代码内容，只记录受控测试计数。性能目标见 architecture.md，未实测不能标通过。

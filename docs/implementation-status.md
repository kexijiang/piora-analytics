# 实现范围与上线边界

2026-11-14 补充：同步策略表单允许任意正整数分钟，移除原先 25/35/120 分钟的业务边界；已保存的间隔与未保存输入分开，侧栏和采集健康显示组织实际策略。客户端通过可选能力请求头声明新范围支持，未声明的旧客户端收到兼容范围；新安装包升级仍以实际发布状态为准。

## 当前明确限制

- 没有生产域名、服务器、员工资料和企业分发配置，因此未部署、未批量启用、未发布 Piora 安装包。个人用户未配置统计时保持关闭。
- 管理 API 提供完整更新、归档、历史绑定纠错、保留和审计接口；首版看板优先提供日常查询、创建、绑定、同步策略，复杂历史纠错/账号停用/保留修改使用已文档化 API。没有做成全部接口的可视化表单。
- 后端实现是 Node.js ESM JavaScript，运行时用 Ajv/OpenAPI 严格校验；前端和协议类型使用 TypeScript。没有把 JavaScript 声称为已做静态类型覆盖的 TypeScript 服务。
- 普通聊天与群聊人工消息计入 Query。群聊扇出创建系统命令，仍只增加一个人工 Query；根消息的多分支生命周期暂不合成一个“全部完成”状态，可能显示待处理。Steer 被消耗的精确归属无法从当前 SDK 确认时，后续调用保留 run 并将 query_id 留空，报质量码。
- 模型观察器在实际 provider stream 边界计数，包含重试和辅助调用。压缩、自动任务等尚无独立上下文的调用归入 system；不能把这部分当人工提交。没有把所有供应商、模型真实付费请求验收写成通过。
- 代码统计覆盖当前 SDK 内置 write/edit。shell、MCP、外部编辑器、同名扩展工具不在保证范围。触及文件数是工具针对的去重文件，包含不可计量操作；新增/删除行和新建文件数仅使用可确认结果。不是 Git 最终贡献或质量评分。
- 文件与差异计量均有预算。超过 2 MiB、100,000 行，或差异搜索超过 50ms/4,000 编辑长度时不输出精确行数，防止统计长时间占用会话进程。文件操作本身仍保留原成功/失败结果。
- 崩溃期间未落盘的模型用量不能恢复。只有开始记录的调用/run 会报告 interrupted，Token/时长为 null。journal 可补回命令事件，但无法制造丢失的真实供应商结算值。
- 网络切换由请求失败后的退避恢复；休眠恢复使用 2–10 分钟抖动。没有增加高频网络心跳。每轮最多五批，剩余积压延后 5–10 分钟。
- 页面分页游标绑定路由/组织/筛选和结果摘要；数据变化使旧游标失效并回首页。没有跨请求冻结并长期存储报表快照。报表展示聚合水位，数据不是实时在线人数。
- 单进程 API 使用内存限流，默认部署单副本。增加 API 副本前应把账号失败计数/限流移到共享存储。查询容量、保留期磁盘、备份恢复和真实锁屏/休眠/安装包仍须试点验证。
